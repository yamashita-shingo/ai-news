# AIニュース記事を制作する

記事制作を依頼されたら、このスキルを使用すると明示してから、ユーザーのテーマを受け取り、記事 Markdown、要約画像、確認用 PR を作る。記事形式は [記事仕様](references/article-format.md)、品質基準は [編集基準](references/editorial.md)、PR と公開は [公開フロー](../../../docs/publishing.md) を必要な段階で参照する。

1. 作業ツリーと既存記事を確認する。テーマが広すぎて記事の対象を特定できないときは確認する。
2. 一次情報を調査し、記事の主張を裏付ける出典と日付を確認する。裏付けが不十分な主張を補わず、調査不能なら理由を報告する。編集基準に従い本文を作る。
3. 利用可能な画像生成ツールで内容を要約する画像を1枚作り、`public/images/` に保存する。代替テキストを付ける。生成できなければ事実を伝え、完成したと偽らない。
4. 同じ本文と確認済み出典を入力として、`../news-comment-critic/SKILL.md`、`../news-comment-expert/SKILL.md`、`../news-comment-reader/SKILL.md` を順に読み、各スキルの使用を明示して A・B・Cのコメントを生成する。役割の違いと事実の裏付けを確認する。
5. 記事仕様に従い `src/content/articles/<slug>.md` を作成し、本文、出典、画像、コメントを見直す。
6. 記事の slug と同名の制作ログを `article-logs/<slug>.md` に作成する。記録内容は `article-logs/README.md` に従い、同じ PR に含める。ログは公開されるため秘密情報は書かない。
7. `npm run check` と `npm run build` を実行し、結果をログに記録する。失敗や実行不能は隠さず報告する。
8. 記事専用ブランチでコミット・プッシュし、記事の内容、出典、検証結果を明記した PR を作る。ユーザーによる確認とマージを待つ。権限不足の場合は残りの操作を報告する。
