# AIニュース記事を制作する

記事制作を依頼されたら、このスキルを使用すると明示してから、ユーザーのテーマを受け取り、記事 Markdown、要約画像、確認用 PR を作る。テーマが指定されずスキルが呼び出されたときは [入力テンプレート](references/input-template.md) を会話に提示し、テーマの回答を待つ。すでにテーマが明確なら再入力を求めず制作を始める。記事形式は [記事仕様](references/article-format.md)、品質基準は [編集基準](references/editorial.md)、PR と公開は [公開フロー](../../../docs/publishing.md) を必要な段階で参照する。

1. 作業ツリーと既存記事を確認する。日付や「今日のAIニュース」のような広いテーマでは、該当日の複数の注目ニュースを調べ、重要性や多様性を考えて選び、一つの記事にまとめる。単一の出来事が明示された場合はそれを中心に扱う。
2. ニュース媒体や解説記事なども活用して調査し、記事の主張を裏付ける出典と日付を確認する。複数の話題を扱う場合は各話題の出典を明確にする。裏付けが不十分な主張を補わず、調査不能なら理由を報告する。編集基準に従い本文を作る。
3. 利用可能な画像生成ツールで内容を要約する画像を1枚作り、記事フォルダに `image.png`（または `image.jpg` / `image.webp`）として保存する。代替テキストを付ける。生成できなければ事実を伝え、完成したと偽らない。
4. 同じ本文と確認済み出典を入力として、`../news-comment-critic/SKILL.md`、`../news-comment-expert/SKILL.md`、`../news-comment-reader/SKILL.md` を順に読み、各スキルの使用を明示して A・B・Cのコメントを生成する。各人物の個性と、事実として述べる内容の裏付けを確認する。
5. 記事仕様に従い `src/content/articles/<slug>/article.md` を作成し、本文、出典、画像、コメントを見直す。
6. 記事フォルダに制作ログ `log.md` を作成する。記録内容は `article-logs/README.md` に従い、同じ PR に含める。ログは公開されるため秘密情報は書かない。
7. ローカルで `npm run check` や `npm run build` は実行せず、PR の GitHub Actions で検証する。制作ログには確認した内容と未検証事項を記録する。
8. 記事専用ブランチでコミット・プッシュし、[公開フロー](../../../docs/publishing.md) の Git 認証情報と GitHub API を使う手順で PR を作る。記事の内容、出典、検証状況とプレビュー URL を PR に記載し、Actions の結果を確認してユーザーによる確認とマージを待つ。認証や権限が不足する場合は残りの操作を報告する。
